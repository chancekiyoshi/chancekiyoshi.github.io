When most people hear "coding standards," they usually think of minor formatting details like tabs versus spaces or where to put curly braces. At first, it seems like extra rules just for the sake of making code look uniform. But after using ESLint in VS Code over the past week, I realized coding standards are actually meant to stop you from making avoidable mistakes and help you learn the language better.

## Resolving an Unexpected Setup Issue

My experience with ESLint didn't start off smoothly. Downloading and installing it was easy enough, but getting it to actually run in VS Code was where the trouble began. We had an assignment where ESLint was supposed to highlight around 30 or more errors in our code to test if it was working. When I ran mine, it only showed 6 errors. 

Finding out why it wasn't working took a while. I had to go step-by-step to troubleshoot configuration settings and extensions, feeling more like an IT technician fixing software on a staff PC than a student writing code. Eventually, with a bit of troubleshooting guidance from Gemini, I got ESLint fully working. As soon as it turned on, all the errors popped up clearly on the screen. The best part of spending all that time fixing it was that I was able to help a classmate who ran into the exact same problem get his setup working, too.

## Learning to Be More Careful

Once ESLint was up and running, it changed how I write code. The constant red and yellow squiggles make you notice things right away instead of finding out something is broken later when you try to run it. 

Having that instant feedback really teaches you to be careful with your code. It keeps you on your toes about things like unused variables or improper syntax before they turn into bigger bugs. Instead of feeling like a strict set of annoying rules, it acts more like an automated guide that keeps your work clean.

## Final Thoughts

Setting up ESLint was tricky at first, but going through the troubleshooting process was a good learning experience. In the end, coding standards aren't just about making your code look pretty—they force you to pay attention to details and build better coding habits from the start.
